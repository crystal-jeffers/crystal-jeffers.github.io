About me

How I work

The same six steps sit behind every project. Each one shows where it happened in my work.

  1. Listen

    I watch how the work actually gets done and listen for friction. The signals I listen for:

    • The same question asked twice
    • A side spreadsheet kept "just in case"
    • "Who has the latest version?"
    • Information re-typed from one place to another
    • A task that only works when one person is in

    In practice: the onboarding system started from the superintendents' own New Hire Protocols, not a blank page.

  2. Spot the real problem

    When something slips, I look at the system before the person. I find the hand-off where things stall and ask what would make the right action the easy one.

    In practice: when several PM parts orders for one customer were hard to tell apart, the fix was a PO numbering system, not more careful typing.

  3. Design with the people who'll use it

    I start from the tools and habits a team already has, give every step one owner, and decide up front which decisions stay with a person.

    In practice: union holiday conflicts are flagged on the dispatch board, never blocked. The supervisor keeps the final call.

  4. Build the smallest version that works

    In the tools the team already uses (Excel, Airtable, OneNote, a simple website), with the guide written alongside the system, not after it.

    In practice: the procedures site runs on plain text files and one settings file. No developer needed.

  5. Iterate from real use

    Replies, questions and workarounds are feedback. I watch the system in use and refine it until people stop working around it.

    In practice: technician follow-ups moved from color-coded lists to clean tables, based on how technicians replied.

  6. Hand it off to last

    Every system ships with documentation for the people who maintain it, so it keeps working as the team grows and changes.

    In practice: the onboarding system's guide site has separate paths for HR and managers, an FAQ for every email, and plain-language definitions.
